# 면면 | 라면 도감, 랭킹, 커뮤니티

한국인의 일상 라면을 한곳에 모은 라면 도감이에요. 먹어 본 사람이 남긴 ‘한 그릇 기록’으로 맛 지도와 라면 랭킹을 만들고, 라면 좋아하는 사람들이 모이는 커뮤니티(후루룩클럽)와 쿠팡 파트너스 라면몰이 함께 들어 있어요.

- **라면 도감(/ramen/)**: 제조사 공식 제품 목록 기준 국내 라면에 편의점(GS25·CU·세븐일레븐·이마트24)과 대형마트(이마트·홈플러스·롯데마트) 자체·단독 라면까지 350가지 넘게(봉지·컵·큰컵 따로). 국물면·비빔면·짜장면·볶음면·컵라면·봉지라면 탭, 회사·형태·맵기·판매 상태 거르기, 초성 검색(예: ㅈㅍㄱㅌ), 기록 많은 순·별점 순 정렬, 책갈피 저장
- **세계 라면 지도(/world/)**: 2025년 나라별 라면 소비량(WINA), 1인당 소비량, 해외 28개 나라 페이지(라면 문화, 주요 회사, 많이 먹는 맛, 참고 자료). 원고는 `content/world.json`이에요.
- **세계 라면 더 읽기**: 세계가 뽑은 라면 TOP 10(/world/best/), 세계 라면 연표(/world/timeline/), 라면 가계도(/world/brands/), 세계 라면 지도의 나라 타일 지도. 원고는 `content/world-more.json`이에요.
- **나에게 맞는 라면 찾기(/lab/match/)**: 질문 다섯 개로 도감 속 라면 세 가지를 추천해요.
- **라면 매니아 코너**: 맵기 사다리(/lab/heat/, 회사가 밝힌 스코빌 지수만), 오늘의 라면 뽑기(/lab/pick/), 라면 퀴즈(/lab/quiz/, 문제는 `content/quiz.json`), 라면 용어 사전(/story/words/, 원고는 `content/words.json`), 라면 성지 여행(/story/places/), 내 도감의 세계 라면 여권(기록한 라면의 나라마다 도장).
- **4차 추가(2026-11-20)**: 라면 도전 과제(/lab/quest/, 목록은 `scripts/pages-more.mjs`의 `QUESTS`에서 도감 자료로 만들고, 표시는 기기 저장 + 로그인 시 한 그릇 기록 반영), 라면 초성 퀴즈(/lab/chosung/, 도감 이름으로 문제 생성), 처음 화면 ‘라면 한 줄 상식’(퀴즈 문제와 해설 재사용), 글 ‘세계의 라면 먹는 법’(/story/eat/)·‘라면 발명 노트’(/story/invent/), TOP 10 페이지에 2026년판·가장 매운 라면·일본 라면 목록(`content/world-more.json`의 `best.lists`, 도감 밖 나라 이름은 `best.others`).
- **라면 그림(2026-11-20, 2026-11-22 보강)**: 라면마다 그림을 ① 허락받은 실물 사진 ② AI 조리 예시 ③ 조리 방식 예시 그림 순서로 골라요. AI 조리 예시는 435가지로, `src/static/img/ramen-ai/`(thumb 1000×800, square 1200×1200, wide 1440×900, 작은 그림 s 400×320, 띠 없는 정사각 q 480×480)에 있고 텍스트로 새로 만든 그림이에요(생성 기록 `content/ai-images.json`). 같은 라면의 다른 이름은 `alias`로 같은 그림을 써요. q는 랭킹·라면몰처럼 정사각 칸에 쓰고, 칸이 큰 곳에는 ‘AI 조리 예시’ 표시를 따로 붙여요. 실물 사진은 `content/photos.json`의 출처별 `allowed`에 허락 기록이 있을 때만 `src/static/img/ramen/`에서 골라 배포해요. 운영 관리 › 라면 사진에서 출처별 현황과 허락 요청 문안을 볼 수 있어요.
- **도감 필터(/ramen/)**: 나라, 맵기, 맛, 조리 방식, 형태, 면을 여러 개 골라 거를 수 있어요. 같은 묶음 안에서는 '또는', 묶음끼리는 '그리고'로 걸러요. 주소에 `?co=jp,th&ta=sour&hot=1`처럼 남아서 그대로 공유할 수 있어요.
- **라면 이야기(/story/)**: 라면의 기원, 1963년 한국 첫 라면, 시장 1위가 바뀐 순간들, 우지 파동, 만드는 법, 종류, 세계 소비·수출 글 7편과 한국 라면 연표. 원고는 `content/story.json`이고 글마다 참고 자료를 밝혀요.
- **라면 페이지(/ramen/신라면 주소/)**: 기본 정보, 평균 별점·종합 순위·또 먹을래요 비율, 여덟 칸 맛 지도(맵기, 짠맛, 단맛, 진하기, 기름짐, 면 굵기, 면 탄력, 개성), 별점 분포, 면 익힘·물 양·넣은 재료, 회원 기록 목록(도움돼요, 신고), 관련 글, 비슷한 라면, 쿠팡으로 사러 가기
- **한 그릇 기록(/record/)**: 별점(반 개 단위)과 ‘또 먹을래요’만 고르면 끝. 맛 지도, 끓인 방법, 넣은 재료, 한 줄 느낌, 메모는 선택. 다시 먹으면 ‘한 번 더 먹었어요’로 횟수가 늘어요
- **랭킹(/rank/)**: 종합, 종류별, 급상승, 신상, 맛 기준, 매니아 픽, 또 먹을래요. 계산식은 평가 기준(/rank/rules/)에 모두 공개
- **취향실험실(/lab/)**: 맛 지도, 라면 비교(최대 3개), 라면 월드컵(8·16·32강), 조리 타이머(계란 알림), 물 양 계산기
- **후루룩클럽(/club/)**: 게시판(라면 토크, 조합·레시피, 시식 후기, 신상 제보, 질문, 투표, 공지), 한 그릇 피드, 시식회·번개(참여 신청, 매너 별점), 사람 랭킹, 등급 안내(첫 봉지 → 면면 명예의 전당 10단계), 배지 22가지, 출석 체크
- **레시피 자랑(/recipes/)**: 후루룩클럽의 사진 레시피 게시판. 사진 다섯 장(브라우저에서 줄이고 위치 정보를 지워서 올려요), 사용한 라면, 재료, 만드는 순서, 조리 시간, 난이도, 꿀팁. 좋아요·저장·공유(카카오톡 등 앱 공유, 링크 복사, X, 페이스북, 밴드), ‘따라 해 봤어요’ 별점 후기(사진 한 장), 댓글, 신고. 레시피 주소(`/recipes/번호`)는 공유했을 때 제목과 대표 사진이 미리보기로 떠요. 처음 화면, 라면 페이지, 클럽 홈에도 레시피가 보여요
- **내 도감(/me/)**: 모은 라면 칸, 라면 일기, 내 입맛(내가 고른 맛 지도), 올해 결산, 저장, 배지, 알림, 설정
- **신상 레이더(/new/)**, **라면몰(/shop/)**, 소개, 문의하기, 이용약관, 개인정보처리방침, 후루룩클럽 이용 규칙
- **운영 관리(/admin/)**: 대시보드, 지표(KPI), 원고 관리, 제보·오류, 문의함, 커뮤니티, 시험 데이터, 쇼핑 링크, 쿠팡 실적 입력, 설정

라면 정보는 제조사 발표와 기사로 확인한 것만 적었어요. 확인하지 못한 칸(형태, 맵기 분류, 출시 시기)은 비워 두었고, 화면에는 ‘확인 중’이나 ‘미분류’로 보여요. 별점과 맛 지도는 회원 기록으로만 계산하고, 운영자가 대신 점수를 매기지 않아요. 라면 카드의 그릇 사진은 조리 방식을 보여 주는 예시 그림이에요.

## 1. Cloudflare에 배포하기

모두 브라우저에서 할 수 있어요. 터미널은 필요 없어요.

### 1-1. Pages 프로젝트 만들기

1. [Cloudflare 대시보드](https://dash.cloudflare.com)에 들어가 왼쪽 메뉴에서 **Workers & Pages**를 눌러요.
2. **Create**(만들기)를 누르고 **Pages** 탭에서 **Connect to Git**(Git에 연결)을 골라요.
   Pages 탭이 보이지 않으면 화면 아래쪽 ‘Looking to deploy Pages?’ 링크를 누르세요.
3. GitHub 계정을 연결하고 이 저장소(`naadaa87/myeonmyeon`)를 골라요.
4. 빌드 설정을 이렇게 넣어요.

   | 항목 | 값 |
   | --- | --- |
   | 프로젝트 이름 | `myeonmyeon` (사이트 주소가 `myeonmyeon.pages.dev`가 돼요) |
   | 프로덕션 브랜치 | `main` |
   | 프레임워크 프리셋 | None (없음) |
   | 빌드 명령 | `npm run build` |
   | 빌드 출력 디렉터리 | `public` |

5. **Save and Deploy**(저장 및 배포)를 누르면 1~2분 뒤 사이트가 열려요.

> 프로젝트 이름을 `myeonmyeon`으로 쓸 수 없어 다른 이름을 썼다면, 이 저장소의 `site.config.json`에서 `siteUrl`을 실제 주소로 바꿔 주세요. 검색 노출용 주소와 공유 이미지 주소가 여기서 정해져요.

### 1-2. 데이터베이스(D1)와 관리자 비밀번호 넣기

도감과 라면 페이지는 이 단계 없이도 열려요. 회원가입, 한 그릇 기록, 랭킹, 후루룩클럽, 운영 관리 화면을 쓰려면 꼭 해 주세요.

1. 대시보드 왼쪽 메뉴에서 **Storage & Databases → D1 SQL Database**(또는 **Workers & Pages → D1**)로 가서 **Create**(만들기)를 눌러요. 이름은 `myeonmyeon-db`로 해요.
2. **Workers & Pages → myeonmyeon → Settings(설정) → Bindings(바인딩)**에서 **Add**(추가) → **D1 database**를 골라요.
   - Variable name(변수 이름): `DB` (대문자 그대로)
   - D1 database: `myeonmyeon-db`
3. 같은 설정 화면의 **Variables and Secrets**(변수 및 비밀)에서 **Add**(추가)를 눌러요.
   - Type(유형): **Secret**(비밀)
   - Variable name: `ADMIN_PASSWORD`
   - Value: 운영 관리 화면에 쓸 비밀번호 (길고 남이 짐작하기 어렵게)
4. 설정은 다음 배포부터 적용돼요. **Deployments**(배포) 탭에서 가장 최근 배포 오른쪽 메뉴(…)를 눌러 **Retry deployment**(배포 다시 시도)를 해 주세요.
5. 확인: 브라우저에서 `https://myeonmyeon.pages.dev/api/health`를 열어 `"db":true,"admin":true`가 보이면 끝이에요.

표(테이블)는 처음 쓸 때 저절로 만들어져요. SQL을 따로 실행하지 않아도 돼요.

### 1-3. 선택 설정 (비밀 값)

| 이름 | 쓰는 곳 |
| --- | --- |
| `COUPANG_ACCESS_KEY`, `COUPANG_SECRET_KEY` | 쿠팡 파트너스 최종 승인 뒤 Open API 키를 넣으면, 운영 관리 › 쇼핑 링크에서 ‘빈 링크 자동 만들기’를 쓸 수 있어요 |
| `INQUIRY_WEBHOOK_URL` | 새 문의가 오면 슬랙·디스코드 웹훅으로 알려 줘요 (개인 정보는 보내지 않아요) |
| R2 바인딩 `PHOTOS` | 레시피 사진 저장소. 아래 ‘사진 저장소(R2) 연결’을 보세요. 없으면 사진을 D1에 저장해요 |
| `AUTH_PEPPER` | 비밀번호 저장을 한 번 더 단단하게 해요. **회원이 생기기 전에만** 넣으세요. 나중에 넣거나 바꾸면 기존 회원이 로그인할 수 없어요 |

### 1-3-1. 사진 저장소(R2) 연결 (사진이 많아지면)

레시피 사진은 처음에는 D1 데이터베이스에 저장해요. 브라우저에서 사진을 줄여 보내서 한 장에 보통 150~300KB 정도예요. D1 무료 한도는 데이터베이스 하나에 500MB라서, 사진이 1,000장을 훌쩍 넘기 전에 R2(사진 같은 파일을 담는 저장소, 무료 10GB)를 붙여 두는 게 좋아요. 지금 쓰는 양은 운영 관리 › 커뮤니티의 ‘최근 레시피 자랑’ 아래에 보여요.

1. 대시보드 왼쪽 메뉴 **Storage & Databases → R2 Object Storage**에서 R2를 켜요. 처음 켤 때 결제 수단을 등록하라고 나올 수 있어요(무료 한도 안에서는 돈이 나가지 않아요). 이 단계는 운영자가 직접 해 주세요.
2. **Create bucket**(버킷 만들기)을 눌러 이름을 `myeonmyeon-photos`로 만들어요.
3. **Workers & Pages → myeonmyeon → Settings → Bindings → Add → R2 bucket**에서 Variable name을 `PHOTOS`, 버킷을 `myeonmyeon-photos`로 골라요.
4. **Retry deployment**로 다시 배포하면, 그 뒤에 올리는 사진부터 R2에 저장돼요. 이미 D1에 있는 사진은 그대로 잘 보여요.

### 1-4. 문 열기 전에 확인할 것

1. `site.config.json`의 `operator`(운영자 이름), `contactEmail`, `privacyEmail`, `privacyOfficer`를 채워 주세요. 개인정보처리방침과 바닥글에 들어가요. 비워 두면 ‘면면 운영팀’으로 보여요.
2. 운영 관리 › **시험 데이터**에서 시험 데이터를 넣어 랭킹·맛 지도·비교 화면을 확인했다면, 알리기 전에 **꼭 지워 주세요.** 시험 데이터가 있는 동안에는 모든 페이지 위에 노란 안내 띠가 떠요.
3. 쿠팡 파트너스 링크를 넣지 않은 라면은 구매 버튼이 쿠팡 검색 결과로 가고, 그때는 수수료가 붙지 않아요. 운영 관리 › **쇼핑 링크**에서 라면마다 파트너스 링크를 붙여 넣어 주세요.
4. 도메인을 연결했다면 `site.config.json`의 `siteUrl`도 그 주소로 바꿔 주세요.

## 2. 운영 관리 화면

`https://myeonmyeon.pages.dev/admin/`에서 위 비밀번호로 들어가요. 로그인은 12시간(‘7일 유지’를 고르면 7일) 이어지고, 비밀번호를 15분 안에 8번 틀리면 잠시 막혀요. 처음 로그인한 브라우저는 방문 통계에서 자동으로 빠져요.

| 메뉴 | 하는 일 |
| --- | --- |
| 대시보드 | 오늘 방문자·페이지뷰·구매 버튼 클릭, 최근 14일 흐름, 할 일(제보, 문의, 신고, 쿠팡 실적 입력, 시험 데이터), 설정 상태 |
| 지표 | 한눈에 보기, 페이지·라면, 유입 경로, 구매·전환, 검색·참여, 실시간 |
| 원고 관리 | 라면 도감·신상 레이더·라면몰 진열대 원고를 GitHub 편집 화면으로 열기, 새 라면 넣는 법, 빈 칸이 남은 라면 목록 |
| 제보·오류 | ‘틀린 정보 알려 주기’로 들어온 제보(정보 오류, 새 라면 제보, 단종·판매처 변경) |
| 문의함 | 문의하기 양식으로 들어온 글, 메모, 이메일 답장 |
| 커뮤니티 | 신고 처리(가리기, 지우기, 문제없음), 운영팀 이름으로 공지·투표 올리기, 글 고정, 최근 기록·글·모임, 회원 이용 제한과 임시 비밀번호 |

## 3. 원고 고치기

원고는 모두 이 저장소의 JSON 파일이에요. GitHub 웹에서 파일을 열고 연필 아이콘(Edit)으로 고친 뒤 **Commit changes**를 누르면, Cloudflare가 1~2분 뒤 사이트에 반영해요. 운영 관리 › 원고 관리에서도 바로 열 수 있어요.

| 파일 | 내용 |
| --- | --- |
| `content/ramen.json` | 라면 도감. 라면 하나가 항목 하나예요 |
| `content/news.json` | 신상 레이더 소식 |
| `content/words.json` | 라면 용어 사전. 링크가 도감에 있는지 빌드할 때 확인해요 |
| `content/quiz.json` | 라면 퀴즈 문제. 보기 4개, 정답 번호, 설명, 더 읽을 곳 |
| `content/world.json` | 세계 라면 지도. 나라 code는 ramen.json의 `co`와 같아야 해요 |
| `content/story.json` | 라면 이야기 글과 연표. `[[ramen:주소\|글자]]`로 도감 링크를 걸어요 |
| `content/shop.json` | 라면몰 진열대 이름, 설명, 진열할 라면 |
| `content/photos.json` | 라면 실물 사진의 출처 목록. 출처의 `allowed`에 허락받은 날짜와 방법을 적어야 그 출처 사진이 화면에 나와요 |
| `content/ai-images.json` | AI 조리 예시 그림의 생성 기록(입력 사진 없음, ‘AI 조리 예시’ 표기) |
| `site.config.json` | 사이트 주소, 운영자, 연락처, 검색 등록 코드 |

### 라면 항목의 칸

| 칸 | 뜻 | 예 |
| --- | --- | --- |
| `s` | 주소(영문 소문자·숫자·하이픈, 다른 라면과 겹치면 안 돼요) | `shin-ramyun` |
| `n` | 이름 | `신라면` |
| `m` | 회사 (`makers`에 있는 이름) | `nongshim` |
| `f` | 형태: `bag` 봉지, `cup` 컵, `bigcup` 큰컵, 모르면 `null` | `bag` |
| `c` | 조리 방식: `soup` 국물, `fried` 볶음, `bibim` 비빔, `jjajang` 짜장, `jjamppong` 짬뽕, `udon` 우동·칼국수, `cold` 냉면·막국수, `etc` 기타 | `soup` |
| `hot` | 편집부 맵기 분류: `0` 순한 편, `1` 매콤, `2` 아주 매운 편, 모르면 `null` | `1` |
| `st` | 판매 상태: `sale` 판매 중, `limited` 한정판, `exclusive` 단독 판매, `off` 단종 | `sale` |
| `ch` | 단독 판매처 (선택) | `GS25` |
| `y` | 출시 연도 또는 연월 (선택) | `2026-01` |
| `shu` | 스코빌 지수와 출처 (제조사·판매처가 밝힌 값만) | `{ "v": 4404, "src": "…" }` |
| `t`, `k` | 맛 태그, 검색어 | `["소고기", "고추"]` |
| `d` | 한두 문장 설명. 확인한 사실만 | |

쉼표 하나가 빠져도 빌드가 멈춰요. 빌드가 멈추면 이전 사이트가 그대로 보이니, 저장한 뒤 Cloudflare의 **Deployments**에서 결과를 확인해 주세요. 빌드 기록 맨 아래에 어느 파일, 어느 라면이 틀렸는지 나와요.

## 4. 랭킹은 이렇게 계산해요

- 한 사람이 라면 하나에 남긴 기록 하나만 세요. 다시 먹고 고치면 새 기록으로 바뀌어요.
- 베이지안 평균: 점수 = n ÷ (n + 20) × R + 20 ÷ (n + 20) × C (R은 그 라면의 평균, C는 전체 평균, n은 기록의 무게 합)
- 기록 무게: 가입 7일 안 × 0.5, 마지막으로 고친 지 12개월이 지난 기록 × 0.7
- 기록 10개 이상인 라면부터 종합 순위에 올라요. 제품을 받아 남긴 기록(‘제품을 받았어요’)은 빼요.
- 순위는 1분마다 다시 계산하고, 주가 시작될 때와 달마다 마지막 순위를 저장해요. 라면몰 ‘이달의 랭킹’은 지난달 마지막 순위를 써요.

기준값은 `server/catalog-data.js`의 `RANK_RULE`에 있고, 평가 기준 페이지도 같은 값을 읽어요.

## 5. 폴더 구조

```
content/            원고 (라면 도감, 라면 이야기, 신상 소식, 라면몰 진열대)
scripts/            빌드 스크립트 (원고 → public/ 정적 페이지)
src/static/         화면 스타일, 스크립트, 그림
server/             서버 기능 (회원, 기록, 랭킹, 커뮤니티, 레시피 자랑·사진, 운영 관리, 지표)
functions/          Cloudflare Pages Functions (/api/*, /go/*, /recipes/번호)
site.config.json    사이트 설정
```

그림(`src/static/img`)은 면면 무드보드에 맞춰 만든 이미지 컷이에요. 라면 카드에는 조리 방식별 그릇 사진(국물·맑은 국물·짜장·볶음·비빔·컵)을 써요.
